单目录本地数据架构与无损迁移

Single-Directory Local-First Data & Lossless Migration
2026-10 LY AI HUB 巨天agent v7.0.0 33 项实测迁移 · 0 丢失
摘要 — 「本地优先」意味着应用的数据架构会像代码一样经历版本演化,而用户数据没有分支可以回退。巨天agent 的运行数据曾分裂在 ~/.laoyou-agent 与 ~/.lyclaw 两处;v7.0.0 将其统一到 ~/.lyclaw 单目录,并内建启动时迁移:旧有新无才搬、搬空才删、失败保留现场下次重试。本文给出迁移算法、冲突处置策略与一次真实迁移的完整记录:33 项成功搬移、12 项重名冲突副本全部保留、配对码跨版本保持不变、零数据丢失。

01问题:演化中的数据目录

产品更名与技术演进(设置从 JSON 迁向 SQLite、技能库共享化)使运行数据分裂在两个用户目录:SQLite 与技能库在 ~/.lyclaw,配对码、截图、记忆、定时任务仍在 ~/.laoyou-agent。旧目录名带着废弃的项目代号,同一个后端读写两处——功能上自洽,但「彻底删除 = 删一个目录」的本地优先承诺已经无法兑现。

合并的约束条件:迁移必须内建于应用启动路径(用户不执行任何命令)、必须幂等(任何一步失败,下次启动接着来)、必须不覆盖新目录已有数据、必须保证手机配对码跨版本连续(已配对的设备不能失效)。

02算法

两条反直觉的保守决策值得单独说明:其一,配对码虽是服务端自生成随机数,但当新旧并存时,保留新目录那份并丢弃旧份——否则旧目录永远差一个文件、永远删不掉,且 token 会在两次构建间来回跳变。其二,skills 里重名但内容不同的旧副本一个都不动:我们无法机械判断哪份是用户改过的,宁可留下一条日志提示人工处置。

03实现

迁移以 IIFE 形式置于 src/server/serve.ts 模块加载的最前端——严格先于 MCP 初始化与 SQLite 打开,保证任何组件首次读到的都是新路径。全部路径经 LYCLAW_HOME / DATA_DIR 两个常量收口(此前 18 处散落的硬编码路径全部替换),并顺带消除一处迁移替换引入的 const DATA_DIR = DATA_DIR 暂态死区崩溃。

05局限

  • 重名冲突副本依赖人工判断,自动化(如按 mtime/内容哈希建议保留方)是后续方向;当前选择「绝不静默删」。
  • 迁移假定同卷(用户主目录内),renameSync 跨卷场景会落入失败分支重试——本产品数据目录恒在同卷,不构成实际路径。
