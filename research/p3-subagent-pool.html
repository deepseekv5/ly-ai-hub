取消安全的并行子代理调度池

A Cancellation-Safe Parallel Sub-Agent Dispatch Pool
2026-10 LY AI HUB 巨天agent v7.0.0 并发 3 · 1–5 agents
摘要 — 让主对话 AI 能「派出 AI」是巨天agent 的核心能力:dispatch_subagents 允许模型一次性派发 1–5 个子代理,每个都拥有完整工具能力。本文描述支撑该能力的调度池设计:固定 worker 池(并发 3)以游标领取任务,取消信号在池内传播并将未启动任务标记为「已取消」、保留已完成产出,进度以窗口事件实时推送至桌面侧栏与手机远程。我们给出机制、可复现参数与端到端数据通路,并明确说明:因执行依赖外部模型服务,本文不报告墙钟时延基准,以避免不可复现的数字。

01问题:并行、可停、可观察,三者兼得

一次调研任务往往可拆为互不依赖的几块。串行执行浪费墙钟时间;无界并发则会在模型速率限制前自我拥塞。更难的是取消语义:用户在 3/5 个子代理完成时按下停止,系统必须回答三个问题——在跑的怎么办?没跑的算什么?已完成的结果丢不丢?此外,进度必须可观察:桌面侧栏与手机远程都要看到每个子代理的阶段与产出。

02设计

取消语义

任务状态(取消瞬间)处置产出
正在执行当前轮完成后停止;若底层请求已中止,以已收到内容收尾尽可能保留部分输出
尚未被领取游标推进时检查 signal.aborted,直接标记「已取消」不产生
已完成不受影响完整保留,汇总时可用

实现上,取消检查放在 worker 领取任务的游标推进处,而非任务内部散点——一处检查覆盖全部未启动任务,语义清晰且无竞态。

03实现与参数

// 调度核心(节选):固定 worker 池 + 游标领取 + 取消检查
const results: string[] = new Array(states.length).fill('')
let cursor = 0
async function worker() {
  while (cursor < states.length) {
    if (opts.signal.aborted) {              // 一处检查,清空全部未启动
      while (cursor < states.length) {
        const s = states[cursor++]; s.status = 'done'; s.phase = '已取消'
      }
      return
    }
    const idx = cursor++                    // 游标领取,天然负载均衡
    await runOne(states[idx], idx)
  }
}
await Promise.all([worker(), worker(), worker()])   // 并发 3

04端到端数据通路

每个子代理的状态机(待命 → 执行中 → 阶段产出 → 完成 / 已取消)经窗口事件 subagent-progress 推送;桌面侧栏 SubAgentTracker 订阅渲染实时进度条;手机远程经由同一事件的服务端桥,在会话流里渲染进度卡片。三端看到的是同一份状态机,不存在各自轮询的口径差。

05局限(诚实声明)

  • 不报告墙钟加速比:端到端时延由外部模型服务的吞吐与限流主导,同一任务在不同 key/时段下差异可达数倍。发布不可复现的加速比曲线违背本实验室的数据原则;机制与参数(并发 3、1–5 派发、取消语义)均为代码事实,可复现。
  • worker 池并发数当前为编译期常量;按任务画像自适应调节是后续方向。
  • 子代理间不共享中间记忆,协作以「主对话汇总」为边界;员工长协作属集群指挥室(另一子系统)。
