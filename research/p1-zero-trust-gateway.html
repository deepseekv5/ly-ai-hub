本地智能体的同宿主零信任网关

A Same-Origin Zero-Trust Gateway for a Local AI Agent Backend
2026-10 LY AI HUB 巨天agent v7.0.0 实测 6/6 攻击拦截
摘要 — 常驻本机的 AI 智能体后端掌握着终端、文件系统与用户密钥,却运行在浏览器可以触达的 localhost 端口上。我们论证了「放开了 CORS 的本地后端」等价于把整台机器的执行权暴露给任意网页,并提出以「同宿主」为核心的零信任网关:只放行与自身 Host 一致的 Origin 与本机回环来源,以 421 拦截 DNS-rebinding,以配对码守卫局域网,以掩码与回写保护双保险处理密钥。该网关已实现于巨天agent v7.0.0,六类攻击向量实测全部拦截,仓库全历史提交经模式扫描零密钥泄漏。

01问题:localhost 不是信任边界

巨天agent 的后端运行在 http://localhost:3211,提供 38 个工具的执行接口——包括任意命令的 shell。用户浏览器里打开的任何网页都可以向这个地址发起 fetch。若后端像传统示例那样返回 Access-Control-Allow-Origin: *,浏览器会拦截响应读取,但请求本身已经执行:一条 /api/tools/execute 足够让网页静默删除文件。而一旦密钥回显接口存在(且带 *),网页更能直接读走用户的 API key。

我们对 v6 时期代码的审计确认了这一形态:GET /api/settings 明文返回全部配置,且所有响应带 Access-Control-Allow-Origin: *。

02设计:四道门,一条链

网关由四个顺序执行的检查构成,任何一道不通过即终止请求:

同宿主判定是核心:Origin 与请求 Host 头一致(协议 + 主机 + 端口)即视为同宿主放行。恶意页面无法伪造与目标 Host 相同的 Origin——浏览器按真实来源填写 Origin;而 DNS-rebinding 场景(页面源与接口源同名)则被下一道「回环来源 + Host 非本机 → 421」兜底。局域网手机远程属于同宿主形态,自然放行,再由配对码门守卫。

密钥的双保险:所有 2xx JSON 回包经过 maskSecrets(sk-6****9Ylc 式掩码,键名包含匹配,使 qq_secret、baiduApiKey 类复合键同样命中);同时,凡含 **** 的值禁止写回存储——客户端整表回传设置时,不会把真密钥冲成掩码垃圾。备份导出是唯一携带明文密钥的出口(否则备份无法还原),它位于门卫链之后,仅本机与已配对设备可达。

03实现

实现于 src/server/serve.ts(构建产物 serve.cjs),核心约 60 行,无第三方依赖:

var isTrustedOrigin = (origin, host) => {
  if (!origin) return true;                    // 同源导航 / curl / Electron
  var o = String(origin);
  if (/^https?:\/\/(127\.0\.0\.1|localhost|\[::1\])(?::\d+)?$/i.test(o)) return true;
  var h = String(host || "").toLowerCase();    // 同宿主:Origin 与 Host 一致
  if (h && (o.toLowerCase() === "http://" + h
         || o.toLowerCase() === "https://" + h)) return true;
  return false;                                // 其余一律 403
};

05局限

  • 同宿主判定信任「Host 头由基础设施正确设置」的前提;在存在反向代理的部署形态下需额外校验(本产品为直连本机形态,不涉及)。
  • 手机远程是局域网信任模型:配对码持有者等同机主,公网隧道被有意排除。
  • 备份导出按设计携带明文密钥以支持完整还原,文件保管责任在用户。
  • npm audit 仍余 22 条中危/高危依赖告警,全部归属 electron 33 / tailwind v3 / pptxgenjs 三个大版本迁移,另行专项处理。
